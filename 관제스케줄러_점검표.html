5. 근무 시작일 기준

한 번에 5가지를 지적하신 부분입니다. 그중 둘은 실제 버그였습니다.

번호요구사항상태확인
5.1몇 일차가 아니라 근무 시작일을 먼저 입력기본값은 설정에 들어온 날짜완료기기 확인
5.2오늘이 아닌 시작일 기준으로 미리보기완료기기 확인 — 시작일부터 7일 미리보기
5.3시작일이 몇 일차인지를 선택으로완료기기 확인
5.4시작일 자체가 안 먹던 문제14일 시작인데 15일까지 휴무로 나옴완료원인: 사이클 기준일이 시작일과 무관했음. anchor = 시작일 − 시작 일차 로 역산하도록 수정
5.5초기화가 오늘 기준이라 시작일 이전 수동 변경이 지워지던 문제완료기준을 오늘 → 근무 시작일로 교체
5.6시작일 이전은 초기화 대신 기존 유지기존 스케줄이 없으면 평일 주간 · 주말 휴무완료기기 확인 — 상세에 "교대 근무 시작 전이라…" 안내 표시
5.7재설정 시 수동 변경을 어떻게 할지 선택하게완료기기 확인 — 그대로 두기 / 시작일 이후만 / 전부 지우기

알고 계셔야 할 것

클라우드 접근 범위
로그인하면 근무표가 Supabase에 올라갑니다. 다른 앱 사용자는 볼 수 없지만, 대시보드 소유자(본인)는 모든 친구의 근무표를 볼 수 있고, Supabase는 종단간 암호화가 아닙니다.
관제 로스터의 성격
근무표는 어느 시간대에 인원이 적은지를 드러냅니다. 팀원과 코드를 교환하기 전에 회사 정책을 확인해 보시는 편이 좋습니다.
업로드 끄기
설정 › 친구 근무표 › 로그아웃 하면 업로드가 멈추고 앱은 완전히 로컬로 돌아갑니다. 이미 올라간 자료는 Supabase 대시보드에서 지우시면 됩니다.
키 관리
local.properties는 저장소에 올라가지 않습니다. service_role 키는 앱에 넣으면 안 됩니다 — 모든 접근 제한을 무시합니다.
